# 4. Premium-priced tracks

**Difficulty:** Easy  
**Track / database:** SQL / Chinook  
**Practice status:** Final solution saved; viva closed; execution not verified

## Question

Using the `Track` table in the Chinook database, the merchandising team wants to review every track that is priced above the standard $0.99 tier. Return the tracks whose `UnitPrice` is **strictly greater than 0.99**.

Output exactly two columns named `Name` and `UnitPrice`.

Sort the result by `UnitPrice` descending, then by `Name` ascending (A to Z) to break ties.

**Expected output:** `Name`, `UnitPrice` · 213 rows · order matters.

Source: [PrepNPlaced SQL practice](https://www.prepnplaced.com/data-practice), “Premium-priced tracks”.

## My thinking process

- I explained that `HAVING` applies a filter to groups.
- When asked what `WHERE` filters in my query, I identified the condition `Track.UnitPrice > 0.99`.
- I chose `>` because the question explicitly requires a price strictly greater than 0.99.
- I added `Track.Name asc` after `Track.UnitPrice desc` because the question requires prices in descending order, then names in ascending order to break ties.

## My solution

### My final solution

I shared this as my final solution. Compared with my first attempt, I qualified the columns with `Track` and explicitly aliased the output columns. My SQL is preserved as written.

```sql
select Track.Name as Name , Track.UnitPrice as UnitPrice
from Track
where Track.UnitPrice > 0.99
order by Track.UnitPrice desc , Track.Name asc
```

## What I learned

- I recalled that `HAVING` is used to filter groups.
- The wording "strictly greater than 0.99" led me to use `>` rather than `>=`.
- The second sort column breaks ties in the first: when prices are equal, the track names are ordered A to Z.
