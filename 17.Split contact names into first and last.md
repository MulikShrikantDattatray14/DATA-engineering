# 17. Split contact names into first and last

**Difficulty:** Easy  
**Track / database:** SQL / Northwind  
**Practice status:** My final solution confirmed and saved; viva complete after 3 questions

## Question

The CRM team stores each customer's contact as a single `ContactName` field (for example, `Maria Anders`) and wants it split into two fields for a mail-merge. In the **Customers** table every `ContactName` contains **exactly one space** separating a first name from a last name.

From the **Customers** table, return the `CustomerID`, the original `ContactName`, the part before the first space as `FirstName`, and the part after the first space as `LastName`.

Output exactly four columns named `CustomerID`, `ContactName`, `FirstName`, and `LastName`. Sort by `CustomerID` **ascending (A to Z)**.

**Expected output:** `CustomerID`, `ContactName`, `FirstName`, `LastName` · 93 rows · order matters.

Source: [PrepNPlaced SQL practice](https://www.prepnplaced.com/data-practice), “Split contact names into first and last”.

## My thinking process

When asked what separates the first and last names in `ContactName`, I proposed `split(' ')`. This identifies the single space as the separator and suggests splitting the text on it. After receiving function hints, I wrote `INSTR(ContactName, ' ')` to locate that space. I then proposed separate `SUBSTR` expressions: the first starts at position 1 and uses the space's position as its length; the last starts immediately after the space and uses `len(ContactName)` as its length. After feedback, I subtracted 1 from the first-name length while initially retaining the same last-name expression. In my next revision, I also replaced `len(ContactName)` with `LENGTH(ContactName)`. These choices and corrections are demonstrated in my expressions, with no separate verbal explanation. I then combined the expressions with `CustomerID` and `ContactName` in a full query, retaining my original source table and sorting. After an alias reminder, I added `FirstName` and `LastName` and explicitly confirmed the query as my final answer.

In the final viva answer, I explained that `+1` excludes the space, moves one position ahead, and starts at the first character of the last name.

## My solution

### First attempt

```sql
select `CustomerID`, `ContactName`, `FirstName`, `LastName`
from Customers
order by `CustomerID` asc
```

Chat formatting artifacts (`&#x20;`, nonbreaking spaces, and the Markdown bold wrapper around `Customers`) were removed. The selected column references and query logic are preserved.

### Expression in progress

```sql
INSTR(ContactName, ' ')
```

This was my next submitted expression, not a final query. It locates the space.

### Name-extraction attempt

For `FirstName`:

```sql
SUBSTR(ContactName, 1, INSTR(ContactName, ' '))
```

For `LastName`:

```sql
SUBSTR(ContactName, INSTR(ContactName, ' ')+1, len(ContactName))
```

Chat formatting wrappers and repeated spacing were normalized. The first-name length and `len` function name are preserved without correction.

### Revised name-extraction attempt

For `FirstName`:

```sql
SUBSTR(ContactName, 1, INSTR(ContactName, ' ')-1)
```

For `LastName`:

```sql
SUBSTR(ContactName, INSTR(ContactName, ' ')+1, LENGTH(ContactName))
```

I first corrected the first-name length while retaining `len`, then submitted the expressions above with `LENGTH` in the last-name expression. Chat formatting was normalized without changing my submitted logic. These were submitted as individual expressions before the full-query revision below.

### Revised full-query attempt

```sql
select `CustomerID`, `ContactName`, SUBSTR(ContactName, 1, INSTR(ContactName, ' ')-1), SUBSTR(ContactName, INSTR(ContactName, ' ')+1, LENGTH(ContactName))
from Customers
order by `CustomerID` asc
```

Chat line-break backslashes, nonbreaking spaces, the Markdown bold wrapper around `Customers`, and the inline-code wrapper around the last-name expression were normalized. Identifier backticks were retained. No aliases were added to my attempt.

### My final solution

```sql
select CustomerID, ContactName, SUBSTR(ContactName, 1, INSTR(ContactName, ' ')-1) as FirstName, SUBSTR(ContactName, INSTR(ContactName, ' ')+1, LENGTH(ContactName)) as LastName
from Customers
order by CustomerID asc
```

I explicitly confirmed this as my final answer. Markdown bold wrappers, chat line-break backslashes, `&#x20;`, and repeated spacing were normalized without changing my logic. My use of `LENGTH(ContactName)` is preserved.

## What I learned

Review feedback and revision status:

- The source table and ascending sort by `CustomerID` match the prompt.
- `Customers` contains `CustomerID` and `ContactName`, but has no `FirstName` or `LastName` columns. Those two required output fields must be derived from `ContactName` rather than selected as existing columns.

Guidance supplied after my `split(' ')` suggestion: the separator is correct, but the suggestion is not a complete SQL expression for this task. In SQLite, `INSTR(text, search)` finds the position of text and `SUBSTR(text, start, length)` extracts part of a string. I was invited to try building just the `FirstName` expression first. These function hints were supplied by the interviewer. I subsequently applied `INSTR` to `ContactName` and the single space in a standalone expression.

Review of that expression: it correctly returns the space's position, counting from 1. It does not itself return the first name. The next step is to use the position to determine how many characters to extract before the space.

Feedback on my name-extraction attempt:

- The `LastName` starting position correctly skips the separator by starting immediately after it. I explained this in my own words during the final viva answer.
- The initial `FirstName` length included the space. For the prompt's example, `Maria Anders`, the space is at position 6, so taking 6 characters from position 1 includes a trailing space. I corrected the expression by subtracting 1 from the space's position, excluding the separator.
- SQLite's built-in string-length function is `LENGTH`, rather than `LEN`. This function-name correction was supplied as feedback, and I applied it in my latest expression.

My earlier full-query revision omitted the output aliases. My final query adds `FirstName` and `LastName`, so all four output names now match the prompt.

Comparison feedback: my last-name expression specifies `LENGTH(ContactName)` as the maximum number of characters to take. SQLite returns the available text up to the end of the string, so this works even though fewer characters remain after the starting position. The supplied reference omits that optional length and also takes the remaining text. My expression does not need replacement. This is review feedback, not a separate explanation I supplied.
