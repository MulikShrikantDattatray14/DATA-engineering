# 1. SQL Number of Unique Subjects Taught by Each Teacher

## Question and image

Given the `Teacher` table, calculate the number of unique subjects taught by each teacher in the university.

Return exactly two columns:

- `teacher_id` — the teacher's id
- `cnt` — the number of distinct subjects taught by that teacher

Sort the result by `teacher_id` ascending.

### Example

**Input — Teacher**

| teacher_id | subject_id | dept_id |
|---:|---:|---:|
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 1 | 3 | 3 |
| 2 | 1 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 2 | 4 | 1 |

**Output**

| teacher_id | cnt |
|---:|---:|
| 1 | 2 |
| 2 | 4 |

Teacher 1 teaches subject 2 in two departments and subject 3 in one department, so the distinct-subject count is 2. Teacher 2 teaches four distinct subjects.

The question image was not supplied.

## Schema

**Teacher**  
teacher_id, subject_id, dept_id

- `teacher_id` — integer
- `subject_id` — integer
- `dept_id` — integer
- `(subject_id, dept_id)` is the primary key.

Each row records that a teacher teaches a subject in a department.

## My solution — SQLite

```sql
SELECT
    teacher_id,
    COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

`GROUP BY teacher_id` creates one result row per teacher. `COUNT(DISTINCT subject_id)` counts each subject only once for that teacher, even when the teacher teaches that subject in multiple departments.

## My solution — SQL Server

```sql
SELECT
    teacher_id,
    COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

The same query works in SQLite and SQL Server.

> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../SQL%20Logical%20Query%20Processing%20Order.md).
