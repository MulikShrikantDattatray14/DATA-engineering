# 24. Track counts for every playlist — empty ones included

## Question and image

Produce a track count for **every playlist** in the Chinook database, including playlists that contain no tracks. Empty playlists must show a count of `0`; they must not disappear or show `1`.

Using **Playlist** and **PlaylistTrack**, return exactly three columns:

- `PlaylistId`.
- `PlaylistName` — the playlist's `Name`.
- `TrackCount` — number of tracks on the playlist, with `0` for empty playlists.

Sort by `TrackCount` **descending**, then `PlaylistId` **ascending**.

There are 18 playlists, and several are empty. A result with fewer than 18 rows, or with empty playlists showing `1`, has encountered one of the two classic traps in this question.

**Expected output:** `PlaylistId`, `PlaylistName`, `TrackCount` · 18 rows · order matters.

## My solution — SQLite

```sql
select
    Playlist.PlaylistId as PlaylistId,
    Playlist.Name as PlaylistName,
    count(PlaylistTrack.TrackId) as TrackCount
from Playlist
left join PlaylistTrack
    on Playlist.PlaylistId = PlaylistTrack.PlaylistId
group by Playlist.PlaylistId, Playlist.Name
order by TrackCount desc, PlaylistId asc;
```

## Official solution

```sql
SELECT
    p.PlaylistId,
    p.Name AS PlaylistName,
    COUNT(pt.TrackId) AS TrackCount
FROM Playlist p
LEFT JOIN PlaylistTrack pt ON pt.PlaylistId = p.PlaylistId
GROUP BY p.PlaylistId, p.Name
ORDER BY TrackCount DESC, p.PlaylistId ASC;
```

### What this tests

The interaction between `LEFT JOIN` and `COUNT`: preserving playlists with no tracks while counting those empty playlists as `0` rather than `1`.

For an empty playlist, the `LEFT JOIN` creates one placeholder row where `PlaylistTrack.TrackId` is `NULL`. `COUNT(*)` counts that placeholder row and incorrectly returns `1`, whereas `COUNT(PlaylistTrack.TrackId)` ignores the `NULL` and correctly returns `0`. Therefore, the two clauses work together: `LEFT JOIN` keeps every playlist, and `COUNT` of the right-side key counts its actual tracks.

### The approach

1. Start from `Playlist` and use a `LEFT JOIN` so every playlist remains in the result.
2. Group by both playlist id and name because playlist names are not unique.
3. Count `pt.TrackId`, which ignores the `NULL` placeholder created for an unmatched playlist and therefore returns `0`.
4. Sort by track count descending and playlist id ascending.

### Why this way

An outer join preserves entities with no matching detail rows, while `COUNT(right_table_column)` measures their matches without counting the unmatched placeholder row. This is the standard pattern for reports that must include zero-count groups.

### Common mistakes

- Using an inner join, which removes empty playlists.
- Using `COUNT(*)` after the left join, which reports `1` for an empty playlist.
- Grouping only by playlist name, which merges different playlists that share the same name.
