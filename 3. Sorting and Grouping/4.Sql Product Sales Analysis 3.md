# 4. SQL Product Sales Analysis 3

## Question and image

Given the `Sales` table, find every sale that occurred during the first year in which each product was sold.

For each `product_id`:

1. Identify the earliest year in which the product appears in `Sales`.
2. Return every sales entry for that product from that earliest year.

Return exactly four columns:

- `product_id`
- `first_year` — the product's earliest sales year
- `quantity`
- `price` — the per-unit price

Sort the result by `product_id` ascending.

A product may have multiple sales entries during the same year, so all entries from its first year must be returned.

### Example

**Input — Sales**

| sale_id | product_id | year | quantity | price |
|---:|---:|---:|---:|---:|
| 1 | 100 | 2008 | 10 | 5000 |
| 2 | 100 | 2009 | 12 | 5000 |
| 7 | 200 | 2011 | 15 | 9000 |

**Output**

| product_id | first_year | quantity | price |
|---:|---:|---:|---:|
| 100 | 2008 | 10 | 5000 |
| 200 | 2011 | 15 | 9000 |

The question image was not supplied.

## Schema

**Sales**  
sale_id, product_id, year, quantity, price

- `sale_id` — integer
- `product_id` — integer; foreign key referencing the `Product` table
- `year` — integer
- `quantity` — integer
- `price` — integer; per-unit price
- `(sale_id, year)` is the primary key.
- A product may have multiple sales entries in the same year.

## My solution — SQLite

### Solution 1 — Correlated subquery

```sql
SELECT
    s.product_id,
    s.year AS first_year,
    s.quantity,
    s.price
FROM Sales AS s
WHERE s.year = (
    SELECT MIN(s2.year)
    FROM Sales AS s2
    WHERE s2.product_id = s.product_id
)
ORDER BY s.product_id ASC;
```

The correlated subquery finds the earliest year for the product belonging to each outer sales row. The outer `WHERE` keeps every row whose year matches that product's earliest year, including multiple sales entries from the same first year.

### Solution 2 — Join to an aggregated subquery

```sql
SELECT
    s.product_id,
    f.first_year,
    s.quantity,
    s.price
FROM Sales AS s
JOIN (
    SELECT
        product_id,
        MIN(year) AS first_year
    FROM Sales
    GROUP BY product_id
) AS f
    ON s.product_id = f.product_id
    AND s.year = f.first_year
ORDER BY s.product_id ASC;
```

The inner query calculates one earliest year per product. Joining it back to `Sales` on both `product_id` and `year` retrieves every complete sales row from that first year. Matching both columns prevents sales from later years or from other products from being included.

`GROUP BY` and `HAVING` alone are not appropriate here because the result must also return the `quantity` and `price` from every matching first-year sales row. Grouping only by product collapses those individual rows; selecting ungrouped `quantity` and `price` is unreliable in SQLite and invalid in SQL Server. The grouped subquery should calculate the earliest year, and the outer join should retrieve the complete matching rows.

## My solution — SQL Server

### Solution 1 — Correlated subquery

```sql
SELECT
    s.product_id,
    s.year AS first_year,
    s.quantity,
    s.price
FROM Sales AS s
WHERE s.year = (
    SELECT MIN(s2.year)
    FROM Sales AS s2
    WHERE s2.product_id = s.product_id
)
ORDER BY s.product_id ASC;
```

The same query works in SQLite and SQL Server.


### Solution 2 — Join to an aggregated subquery

```sql
SELECT
    s.product_id,
    f.first_year,
    s.quantity,
    s.price
FROM Sales AS s
JOIN (
    SELECT
        product_id,
        MIN(year) AS first_year
    FROM Sales
    GROUP BY product_id
) AS f
    ON s.product_id = f.product_id
    AND s.year = f.first_year
ORDER BY s.product_id ASC;
```

The same join-based query works in SQLite and SQL Server.

> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
