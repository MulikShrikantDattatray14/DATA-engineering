## Question

The catalog team wants the genre records for **Rock** and **Jazz**. From the **Genre** table, return the rows whose `Name` is either `'Rock'` or `'Jazz'`.

Output exactly two columns named `GenreId` and `Name`.

Sort by `Name` ascending.

**Expected output:** `GenreId`, `Name` · 2 rows · order matters.

## My thinking process

I chose `IN` to keep the filter short instead of repeating the `Name` comparison with `OR` for each genre.

## My solution

My final solution:

```sql
select GenreId,Name
from Genre
where Name In('Rock','Jazz')
order by Name asc
```

Pasted Markdown line-break backslashes and trailing spaces were removed; the SQL logic is unchanged.

My first attempt lacked a separator between the genre values and had outer backticks around them. In my final query, I added the comma and kept single quotes around each text value.

## What I learned

- Correction demonstrated in my final query: separate the values in the `IN` list with a comma.
- Correction demonstrated in my final query: use single quotes for text values; the outer backticks from my first attempt were removed.
- My reason for choosing `IN`: it keeps alternative matches for the same column concise, avoiding repeated comparisons joined with `OR`.
