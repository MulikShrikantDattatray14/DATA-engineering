A valid e-mail has a prefix name and a domain where:

The prefix name is a string that may contain letters (upper or lower case), digits, underscore '_', period '.', and/or dash '-'. The prefix name must start with a letter.

The domain is '@bosscoderacademy.com'.

Return the result table in any order.

<summary>Class-provided reference solution (open after your attempt)</summary>

The following SQL was supplied in the class notes. It is kept separate from your pending solution.

```sql
SELECT *
FROM Users
WHERE REGEXP_LIKE(mail, '^[A-Za-z][A-Za-z0-9._-]*@leetcode[.]com$', 'c');
```

### What this tests

Validating an entire string against prefix, allowed-character, and domain rules.

### The approach

The supplied regular expression anchors the match at both ends. It requires an initial letter, permits the listed characters in the rest of the prefix, and matches the literal `@leetcode.com` domain. The supplied `'c'` match option requests case-sensitive matching in the reference's regex syntax.

### Why this way

Anchors prevent a valid-looking substring from being accepted inside a longer invalid address. `[.]` matches a literal period in the domain.

### Common mistakes

- Using the wrong domain: this exact supplied reference filters `leetcode.com`, so it does not solve the written `bosscoderacademy.com` version and would not return the displayed output for the supplied sample.
- Forgetting to require a letter as the first prefix character.
- Using an unescaped dot that matches any character.
- Treating `REGEXP_LIKE` as a built-in function available in every SQL engine. This is the class-provided reference syntax, not the learner's SQLite or SQL Server solution.

**Source inconsistency:** Under the written domain rule, David should also appear. Under the supplied reference's domain filter, none of the supplied addresses qualifies. Resolve which version to practice before treating the supplied output or reference as authoritative.
