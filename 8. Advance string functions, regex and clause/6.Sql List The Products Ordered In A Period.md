# 6. SQL List The Products Ordered In A Period

## Question and image

Write a solution to get the names of products that have at least 100 units ordered in February 2020 and their amount.

Return the result table in any order.

Table: Products

| Column Name | Type |
|---|---|
| product_id | int |
| product_name | varchar |
| product_category | varchar |

product_id is the primary key (column with unique values) for this table.

This table contains data about the company's products.

Table: Orders

| Column Name | Type |
|---|---|

The following SQL was supplied in the class notes. It is kept separate from your pending solution.

```sql
SELECT
    p.product_name,
    SUM(o.unit) AS unit
FROM
    Products p
JOIN
    Orders o
    ON p.product_id = o.product_id
WHERE
    o.order_date LIKE '2020-02-%'
GROUP BY
    p.product_id
HAVING
    SUM(o.unit) >= 100;
```

### What this tests

Joining product details to orders, filtering a period, and applying a condition to an aggregated total.

### The approach

Join `Products` and `Orders` on `product_id`, retain orders whose date matches the February 2020 prefix, group by product ID, and retain groups with a total of at least 100 units.

### Why this way

`WHERE` restricts the rows included in the total. `HAVING` checks the total after grouping. Grouping by product ID keeps distinct products separate even if their names match.

### Common mistakes

- Testing the 100-unit requirement against each order rather than the product's total.
- Counting order rows instead of summing `unit`.
- Including orders outside February 2020 or discarding legitimate duplicate rows.
- Assuming the supplied query is SQL Server compatible. It selects `product_name` while grouping only by `product_id`, and its date-prefix `LIKE` depends on date representation. This reference uses SQLite/MySQL-style syntax; a final SQL Server adaptation is still pending.
