# 8. SQL Warehouse Manager

## Question and image

**8. Sql Warehouse Manager**

Table: Warehouse

| Column Name | Type |
|---|---|
| name | varchar |
| product_id | int |
| units | int |

`(name, product_id)` is the primary key (combination of columns with unique values) for this table. Each row of this table contains the information of the products in each warehouse.

Table: Products

| Column Name | Type |
|---|---|
| product_id | int |
| product_name | varchar |
| Width | int |
| Length | int |
| Height | int |

`product_id` is the primary key (column with unique values) for this table.

Each row of this table contains information about the product dimensions (Width, Lenght, and Height) in feets of each product.

Write a solution to report the number of cubic feet of volume the inventory occupies in each warehouse.

The query result format is in the following example.

**Example 1:**

Input:

Warehouse table:

| name | product_id | units |
|---|---|---|
| LCHouse1 | 1 | 1 |
| LCHouse1 | 2 | 10 |
| LCHouse1 | 3 | 5 |
| LCHouse2 | 1 | 2 |
| LCHouse2 | 2 | 2 |
| LCHouse3 | 4 | 1 |

Products table:

| product_id | product_name | Width | Length | Height |
|---|---|---|---|---|
| 1 | LC-TV | 5 | 50 | 40 |
| 2 | LC-KeyChain | 5 | 5 | 5 |
| 3 | LC-Phone | 2 | 10 | 10 |
| 4 | LC-T-Shirt | 4 | 10 | 20 |

Output:

| warehouse_name | volume |
|---|---|
| LCHouse1 | 12250 |
| LCHouse2 | 20250 |
| LCHouse3 | 800 |

Explanation:

Volume of product_id = 1 (LC-TV), 5x50x40 = 10000

Volume of product_id = 2 (LC-KeyChain), 5x5x5 = 125

Volume of product_id = 3 (LC-Phone), 2x10x10 = 200

Volume of product_id = 4 (LC-T-Shirt), 4x10x20 = 800

LCHouse1: 1 unit of LC-TV + 10 units of LC-KeyChain + 5 units of LC-Phone.

1. Total volume: 1*10000 + 10*125 + 5*200 = 12250 cubic feet

LCHouse2: 2 units of LC-TV + 2 units of LC-KeyChain.

1. Total volume: 2*10000 + 2*125 = 20250 cubic feet

LCHouse3: 1 unit of LC-T-Shirt.

1. Total volume: 1*800 = 800 cubic feet.

## Schema

**Warehouse**  
name, product_id, units

- `name` — varchar
- `product_id` — integer
- `units` — integer
- (`name`, `product_id`) is the primary key.

**Products**  
product_id, product_name, Width, Length, Height

- `product_id` — integer; primary key
- `product_name` — varchar
- `Width` — integer
- `Length` — integer
- `Height` — integer

## My solution — SQLite

```sql
SELECT
    Warehouse.name AS warehouse_name,
    SUM(
        Products.Width
        * Products.Length
        * Products.Height
        * Warehouse.units
    ) AS volume
FROM Warehouse
JOIN Products
    ON Warehouse.product_id = Products.product_id
GROUP BY Warehouse.name;
```

### Key learnings

- `Width * Length * Height` calculates the cubic-foot volume of one unit of a product.
- Multiplying the per-unit volume by `Warehouse.units` calculates the total volume occupied by that product in the warehouse.
- `SUM(...)` adds the occupied volumes of all products stored in the same warehouse.
- `GROUP BY Warehouse.name` creates one result row for each warehouse.
- `Warehouse.name AS warehouse_name` gives the output column the required name.
- Joining through `product_id` connects each warehouse inventory row to the corresponding product dimensions.
- An inner `JOIN` clearly expresses that a matching product row is required to calculate volume.
#### Why the inner join is used

The required information is split between two tables:

- `Warehouse` provides the warehouse, product, and number of units.
- `Products` provides the product's width, length, and height.

The inner `JOIN` matches their shared `product_id` and places the units and dimensions on the same row. SQL can then calculate `units * Width * Length * Height`. A warehouse inventory row without matching product dimensions cannot have its volume calculated, so only matching rows are needed.
## My solution — SQL Server

```sql
SELECT
    Warehouse.name AS warehouse_name,
    SUM(
        Products.Width
        * Products.Length
        * Products.Height
        * Warehouse.units
    ) AS volume
FROM Warehouse
JOIN Products
    ON Warehouse.product_id = Products.product_id
GROUP BY Warehouse.name;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
