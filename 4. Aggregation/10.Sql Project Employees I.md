# 10. SQL Project Employees I

## Question and image

**10. Sql Project Employees I**

Table: Project

| Column Name | Type |
|---|---|
| project_id | int |
| employee_id | int |

`(project_id, employee_id)` is the primary key of this table.

`employee_id` is a foreign key to Employee table.

Each row of this table indicates that the employee with `employee_id` is working on the project with `project_id`.

Table: Employee

| Column Name | Type |
|---|---|
| employee_id | int |
| name | varchar |
| experience_years | int |

`employee_id` is the primary key of this table. It's guaranteed that `experience_years` is not NULL.

Each row of this table contains information about one employee.

Write an SQL query that reports the average experience years of all the employees for each project, rounded to 2 digits.

The query result format is in the following example.

**Example 1:**

Input:

Project table:

| project_id | employee_id |
|---|---|
| 1 | 1 |
| 1 | 2 |
| 1 | 3 |
| 2 | 1 |
| 2 | 4 |

Employee table:

| employee_id | name | experience_years |
|---|---|---|
| 1 | Khaled | 3 |
| 2 | Ali | 2 |
| 3 | John | 1 |
| 4 | Doe | 2 |

Output: 

| project_id | average_years |
|---|---|
| 1 | 2.00 |
| 2 | 2.50 |

*Explanation: The average experience years for the first project is (3 + 2 + 1) / 3 = 2.00 and for the second project is (3 + 2) / 2 = 2.50*

## Schema

**Project**  
project_id, employee_id

- `project_id` — integer
- `employee_id` — integer; foreign key to `Employee.employee_id`
- (`project_id`, `employee_id`) is the primary key.

**Employee**  
employee_id, name, experience_years

- `employee_id` — integer; primary key
- `name` — varchar
- `experience_years` — integer; not `NULL`

## My solution — SQLite

```sql
SELECT
    P.project_id AS project_id,
    ROUND(
        SUM(E.experience_years) * 1.0 / COUNT(P.employee_id),
        2
    ) AS average_years
FROM Project AS P
JOIN Employee AS E
    ON P.employee_id = E.employee_id
GROUP BY P.project_id;
```

### Key learnings

- The `Project` table identifies which employees belong to each project, while `Employee` provides their experience years.
- Joining on `employee_id` places the project assignment and employee experience on the same row.
- `GROUP BY P.project_id` creates one group for each project.
- `SUM(E.experience_years) / COUNT(P.employee_id)` calculates the average manually.
- Multiplying the sum by `1.0` forces decimal division in SQLite.
- Without `* 1.0`, a calculation such as `5 / 2` may become `2`, discarding the required `0.5` before `ROUND()` runs.
- `ROUND(..., 2)` rounds the decimal result to two places.
- `AS average_years` provides the exact required output column name.
- `AVG(E.experience_years)` would be a simpler equivalent aggregate, but this solution preserves the manual average calculation.
## My solution — SQL Server

```sql
SELECT
    P.project_id AS project_id,
    ROUND(
        SUM(E.experience_years) * 1.0 / COUNT(P.employee_id),
        2
    ) AS average_years
FROM Project AS P
JOIN Employee AS E
    ON P.employee_id = E.employee_id
GROUP BY P.project_id;
```

The same query works in SQLite and SQL Server. Multiplying by `1.0` forces decimal division in both.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
