# 1. SQL Immediate Food Delivery I

## Question and image

**1. Sql Immediate Food Delivery I**

Table: Delivery

| Column Name | Type |
|---|---|
| delivery_id | int |
| customer_id | int |
| order_date | date |
| customer_pref_delivery_date | date |

`delivery_id` is the primary key (column with unique values) of this table.

The table holds information about food delivery to customers that make orders at some date and specify a preferred delivery date (on the same order date or after it).

If the customer's preferred delivery date is the same as the order date, then the order is called immediate; otherwise, it is called scheduled.

Write a solution to find the percentage of immediate orders in the table, rounded to 2 decimal places.

The result format is in the following example.

**Example 1:**

Input:

Delivery table:

| delivery_id | customer_id | order_date | customer_pref_delivery_date |
|---|---|---|---|
| 1 | 1 | 2019-08-01 | 2019-08-02 |
| 2 | 5 | 2019-08-02 | 2019-08-02 |
| 3 | 1 | 2019-08-11 | 2019-08-11 |
| 4 | 3 | 2019-08-24 | 2019-08-26 |
| 5 | 4 | 2019-08-21 | 2019-08-22 |
| 6 | 2 | 2019-08-11 | 2019-08-13 |

Output:

| immediate_percentage |
|---|
| 33.33 |

*Explanation: The orders with delivery id 2 and 3 are immediate while the others are scheduled.*

## Schema

**Delivery**  
delivery_id, customer_id, order_date, customer_pref_delivery_date

- `delivery_id` — integer; primary key
- `customer_id` — integer
- `order_date` — date
- `customer_pref_delivery_date` — date on or after `order_date`

## My solution — SQLite

```sql
WITH immediate AS (
    SELECT
        COUNT(delivery_id) AS immediate_count
    FROM Delivery
    WHERE order_date = customer_pref_delivery_date
),
total_count AS (
    SELECT
        COUNT(delivery_id) AS total_count
    FROM Delivery
)
SELECT
    ROUND(immediate_count * 100.0 / total_count, 2)
        AS immediate_percentage
FROM immediate
CROSS JOIN total_count;
```

### Key learnings

- The `immediate` CTE returns one row containing the number of orders whose preferred delivery date equals their order date.
- The `total_count` CTE returns one row containing the total number of orders.
- A `CROSS JOIN` creates every possible combination of rows from two tables. If one table has `m` rows and the other has `n` rows, the result contains `m × n` rows.
- Here, both CTEs contain exactly one row, so the `CROSS JOIN` creates one combined row containing both `immediate_count` and `total_count`.
- Combining the two counts into one row allows the final `SELECT` to divide one value by the other. A `CROSS JOIN` does not require an `ON` condition.
- `100.0` forces decimal division in SQLite. Using integer values could truncate the division result.
- `ROUND(..., 2)` rounds the percentage to two decimal places, and `AS immediate_percentage` provides the required output column name.
## My solution — SQL Server

```sql
WITH immediate AS (
    SELECT
        COUNT(delivery_id) AS immediate_count
    FROM Delivery
    WHERE order_date = customer_pref_delivery_date
),
total_count AS (
    SELECT
        COUNT(delivery_id) AS total_count
    FROM Delivery
)
SELECT
    ROUND(immediate_count * 100.0 / total_count, 2)
        AS immediate_percentage
FROM immediate
CROSS JOIN total_count;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation.
