# 15. Order roster with customer and employee names

**Difficulty:** Easy  
**Track / database:** SQL / Northwind  
**Practice status:** My final solution confirmed and saved; viva complete after 2 questions

## Question

Using the Northwind database, build a roster that pairs every order with the customer who placed it and the employee who handled it. Join `Orders` to `Customers` (on `CustomerID`) and to `Employees` (on `EmployeeID`).

Return exactly these three columns:

- `OrderID`: the order's id.
- `CustomerName`: the customer's `CompanyName`.
- `EmployeeName`: the employee's first and last name joined by a single space, e.g. `Nancy Davolio`.

Return **one row per order**. Sort the result by `OrderID` **ascending**.

**Expected output:** `OrderID`, `CustomerName`, `EmployeeName` · 16282 rows · order matters.

Source: [PrepNPlaced SQL practice](https://www.prepnplaced.com/data-practice), “Order roster with customer and employee names”.

## My solution

### First attempt

```sql
select `Orders`. OrderID , `Customers` . CompanyName , `Employees`.FirstName | ' '| LastName as EmployeeName
from `Orders`
join `Customers` on `Orders`.CustomerID = `Customers` .CustomerID
join `Employees` on `Customers`.EmployeeID = `Employees` .EmployeeID
order by `OrderID` asc
```

Chat formatting artifacts (`&#x20;` and nonbreaking spaces) and repeated spacing were normalized. The single-pipe operators, employee join reference, and missing customer-name alias are preserved from my attempt.

### Second revision

The changed starting table and join order are preserved. Chat formatting artifacts and repeated spacing were normalized; the employee join reference was not repaired.

### My final solution

```sql
select Orders. OrderID as OrderID , Customers. CompanyName as CustomerName , Employees.FirstName || ' ' || LastName as EmployeeName
from Customers
join Orders on Orders.CustomerID = Customers .CustomerID
join Employees on Orders.EmployeeID = Employees.EmployeeID
order by OrderID asc
```

My third revision corrected the employee join to read the employee ID from `Orders`. I then explicitly confirmed the query above as my final solution, adding the explicit `OrderID` alias and removing identifier backticks. Repeated spacing was normalized without changing my query's logic.
