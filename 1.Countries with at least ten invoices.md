## My thinking process

1. "Each country" means I need to group the invoices by country, so I use `GROUP BY BillingCountry`.
2. "Countries with invoices >= 10" means I need to count the invoices in each group and filter those groups using `HAVING` and `COUNT(*)`.
3. I added the required sorting: invoice count in descending order, then country in ascending order to break ties.
4. I corrected the table name from `invoice` to `Invoice` to match the case-sensitive schema provided by the question.

## My solution

This is the query I developed during the discussion.

```sql
select BillingCountry as Country, count(*) as InvoiceCount
from Invoice
group by BillingCountry
having count (*) >=10
order by InvoiceCount desc, Country asc
```

## What I learned

- `GROUP BY` forms one group per country so I can count invoices for each country.
- `COUNT(*)` counts the rows in each group; here, each row represents an invoice.
- `WHERE` filters individual rows before grouping, while `HAVING` filters groups after aggregation.
- The "at least 10 invoices" condition depends on the count for a country, so it belongs in `HAVING`.
- "At least 10" includes exactly 10, so the comparison is `>= 10`.
- Aliases must match the requested output names: `Country` and `InvoiceCount`.
- Sorting needs both the primary order and the tie-breaker: highest invoice count first, then country A-Z when counts match.
- I need to check table-name capitalization and keep chat formatting such as backslashes and `**` out of the SQL editor.

### My explanation of HAVING versus WHERE

> HAVING is used to apply a filter on grouping, while WHERE is used to filter out rows.

The timing makes this more precise: `WHERE` acts before grouping, and `HAVING` acts after aggregation.
